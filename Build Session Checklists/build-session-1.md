# Build Session 1 Checklist

The goal of Build Session 1 is to leave with enough evidence that you are framing a **real, valuable, and buildable problem**.

You do not need the full solution yet.

You need confidence that the problem is worth solving.

## 1. Problem Evidence

Check each condition before moving too far into building.

### The problem is real

- [ ] I experience this problem myself
- [ ] I am the **N of 1** user
- [ ] I can clearly describe when and why the problem occurs
- [ ] The problem is not hypothetical or invented for the Datathon

### The problem deserves a solution

- [ ] The problem is complex enough that a single prompt or Google search does not already solve it
- [ ] Solving it would create meaningful value
- [ ] Existing tools do not already solve the problem just as well or better
- [ ] I can explain what is missing from the current alternatives

### The scope is right

Your problem should sit somewhere in the middle:

```text
Too Small                                              Too Large
│                                                         │
│  Google Search   Single Prompt   Microproduct   Full Company / Platform
│        ✗               ✗              ✓                    ✗
│                                                         │
└───────────────────────────────●─────────────────────────┘
                         Aim around here
```

- [ ] The problem is narrow enough to make meaningful progress during the Datathon
- [ ] The solution does not require building an entire platform or company
- [ ] I can define what a useful first version looks like

---

## 2. Data Evidence

Assuming data is a key part of your solution, confirm that it is actually usable.

### Accessibility

- [ ] I know where the required data comes from
- [ ] I can realistically access it during the Datathon
- [ ] I have enough data to begin testing the idea

### Permission

- [ ] I understand the license or terms of use
- [ ] I am allowed to use the data for my intended purpose
- [ ] I understand whether the data can be used commercially, educationally, or only under specific restrictions

### Signal

- [ ] The data contains information relevant to the problem
- [ ] I believe there is enough signal in the data to support a useful solution
- [ ] I have enough coverage, quality, and volume to test that assumption

---

## Build Session 1 Exit Condition

By the end of the session, you should be able to say:

> **I have a real problem, I am the first user, solving it creates meaningful value, the scope is buildable, and I have access to data that can reasonably help solve it.**
